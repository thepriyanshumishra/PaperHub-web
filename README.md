# 📄 PaperHub — Premium University Exam Preparation

> **"A premium university exam preparation environment."** — Designed to feel like VS Code for exam prep.

PaperHub is a university-focused, structured exam preparation platform built for **descriptive/written university examinations**. It transforms scattered PDFs, WhatsApp PYQs, and random Drives into a topic-wise, syllabus-aware preparation hub powered by **Groq AI** step-by-step solutions and **Llama 4 Vision** grading.

## 🚀 Getting Started

### 1. Prerequisites
- [Node.js](https://nodejs.org/) v18+  
- A [MongoDB Atlas](https://www.mongodb.com/atlas) cluster (free tier works fine)  
- A [Groq API key](https://console.groq.com/) (free tier, very fast)

### 2. Clone & Install
```bash
git clone https://github.com/thepriyanshumishra/PaperHub-web.git
cd PaperHub-web
npm install
```

### 3. Environment Variables
Create `.env.local` in the project root:
```env
MONGODB_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/paperhub?retryWrites=true&w=majority
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

### 4. Seed the Database
Populate your Atlas cluster with colleges, branches, subjects, units, and past-year questions:
```bash
npx tsx scripts/seed.ts
```

### 5. Start the Dev Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) and complete onboarding to start practicing.

## 🔒 Security Hardening

To ensure production readiness, the application implements the following security protocols:

### A. Dual-End File Validation
- **Frontend Validation**: Blocks uploads of non-image files on the client. Enforces a maximum file size of **10 MB**, checks allowed extensions (`.jpg`, `.jpeg`, `.png`, `.webp`), and allowed MIME types (`image/jpeg`, `image/png`, `image/webp`).
- **Backend Validation**: Strictly parses the base64 input array. Enforces a dynamic upload limit of **3 pages per question** (capped at a maximum of **30 pages total** per test session) to safeguard database storage. Ensures MIME types conform to images via regex pattern matching, and caps base64 string lengths at `14,500,000` characters (~10MB) per image.
- **Vision Batch Processing**: To handle larger uploads (up to 30 pages) without hitting API payload size or token limits, the backend automatically batches images in chunks of 5, evaluates them sequentially using `meta-llama/llama-4-scout-17b-16e-instruct`, and merges the grades by choosing the highest-scoring question details.

### B. Abuse Prevention & Memory Leak Fix
- **Edge Rate Limiting**: Matches `/api/ai/*` to throttle automated/malicious traffic.
- **Cache Self-Pruning**: The in-memory edge limiter automatically prunes expired tracking entries whenever the Map grows beyond `1,000` entries, avoiding memory exhaustion.

## 🤖 AI Models Integration

PaperHub integrates with Groq's high-speed endpoint to provide low-latency study feedback:

| Feature / Route | Target AI Model | Caching Behavior |
|---|---|---|
| `GET /api/ai/solve` | `llama-3.3-70b-versatile` | ✅ Cached in MongoDB (`question.cachedSolution`) |
| `POST /api/ai/solve` | `llama-3.3-70b-versatile` | ❌ Live execution (no cache) |
| `POST /api/ai/explain-step` | `llama-3.3-70b-versatile` | ❌ Always Live |
| `POST /api/ai/chat` | `llama-3.1-8b-instant` | ❌ Scoped live conversation |
| `POST /api/ai/evaluate` | `meta-llama/llama-4-scout-17b-16e-instruct` | ❌ Vision OCR grading model |

*Fallback logic is in place for all endpoints, shifting to `llama-3.1-8b-instant` in case of API rate limits or downtime.*
